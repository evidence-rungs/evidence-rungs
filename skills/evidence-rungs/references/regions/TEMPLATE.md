# Optional region reference template

Use a short region code and one file per topic; do not change the core method's default jurisdiction. Provide links and your own one-line roles only, not downloaded documents, excerpts, logos, or datasets. A regional reference does not grant access rights.

Header: region and topic; reviewed YYYY-MM-DD; review due YYYY-MM; evidence language; territorial/legal scope. Review law/consumer/health at least every six months, rapidly changing technology/community sources every three months. An overdue date is a warning, not proof that content is false.

Contribution record (required for new or revised cards): provenance URL(s) and original authoring statement; jurisdiction and exclusions; source/version date when known; checked-on date; reviewer public handle or role; maintenance owner public handle or role; review-due date. Do not invent a reviewer or expose a private name. Existing inherited cards have dated source notes but no independent reviewer recorded; treat them as unreviewed references until reviewed.

For each verified public link: exact host and useful path; role (primary, specialist, independent test, practitioner/community, aggregator); where it applies; what it can establish; one key limitation/access condition. Keep official law distinct from advice, product approval from efficacy, and measurements from owner anecdotes. Mark unknown endpoints/access as unverified and omit speculative API templates.

Check original ownership and redirects; a look-alike host is not the institution. Sources outside a reference need the core quality/origin gate. Include a primary-source alternative when available; do not invent one when blocked. Preserve dated provenance and third-party rights, and record who will maintain a future contribution before adding it. A URL is not evidence of present availability, current law, or a license to copy text.
